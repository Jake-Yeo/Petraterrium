# Missing evidence and framework depth

This file records every known gap that currently needs a fallback. A fallback is part of the output receipt; it is never evidence that the missing input was measured.

| Missing item | Current fallback | What closes it | Impact |
| --- | --- | --- | --- |
| Fitted coefficients for the bundled smoke run | Values labelled `FAKE` and `literature_estimate`, with uncertainty 0.8 | Joint trait-and-outcome data, a held-out fit, and a versioned evidence-table entry | Smoke outcomes prove plumbing and determinism only; they do not predict people |
| Measured population for Northport and Southport | A 1,200-row `FAKE` population with explicit place totals and simple age defaults | Census or licensed microdata reweighted to dated marginals | Agent traits and network structure are illustrative |
| Real individual histories for mass agents | Deterministic representative projection from recorded place counts; the UI labels the projection `FAKE` or representative | Weighted agent-state persistence or statistically exact cohort tracking per tick | Clicking a mass row proves the drill-down contract, not a fully persisted personal causal history |
| Large-scale spatial indexing | The Simulation runner stores exact hierarchical locations, evidence-backed transit states, place availability, and per-agent location history; legacy globe point queries remain viewport-limited and scan the in-memory sample | An indexed spatial store for mass-agent globe queries | Simulation movement and co-location are explicit, while very large legacy globe queries remain memory-bound |
| Production Monte Carlo execution | Anchor replay module plus one explicit `1/1` SSE ensemble update | Worker-backed multi-seed execution, quantile aggregation, and cache eviction | A smoke run is labelled as a single sample and must not be called a prediction distribution |
| External run workers and resumable active jobs | SQLite durably stores run metadata, daily frames, events, final agent state, and completed results; execution still uses an in-process worker and an interrupted run fails explicitly after restart | Job leases, external worker retries, and checkpoint resume | Completed runs survive API restarts; an active run does not resume after process loss |
| Backtest route and saved comparison workflow | No-hindsight backtest function and typed output contract | Dated observed-series import, API endpoint, saved comparison UI, and multiple real benchmarks | Backtest correctness is unit tested but not yet a complete product flow |
| Rich newsroom scheduling | Threshold events, exact template stories, arcs, and story API | Weekly dedupe/scoring, lazy validated hero narration, outlet variants, follows, and counterfactual branches | Story numbers are auditable, while newsroom breadth is limited |
| Measured joint distributions requested in the Data tab | Complete measured joint tables marked for population sampling preserve their recorded correlations at the most specific place; incomplete query records remain display-only, while missing tables use labelled marginal products and create an exact record in `missing_joint_requests` | A weighted respondent-level extract measuring every selected feature in the same rows, with source, sample size, date, geography, confidence interval, and a complete probability table | Places without a complete measured table still receive exploratory marginal sampling that cannot claim correlation or fit a joint coefficient |
| Measured household composition and relationship joints | Complete measured household tables create linked spouse, parent, and child roles within their recorded age constraints; places without one use deterministic household-size marginals and keep composition and family relationships imputed or unknown | Weighted household microdata with person IDs, relationship-to-head, spouse/partner links, parent-child links, ages, geography, and survey weights | Measured tables preserve recorded family composition; fallback households remain internally consistent without claiming measured roles |
| Direct city distributions for the universal feature registry | Country or regional distributions inherit to cities with the source place retained | Representative city samples or disclosure-safe census aggregates with city boundaries, dates, weights, and sampling frames | City agents can be generated from inherited evidence, but the organizer must not label that evidence city-measured |
| Direct age and sex distribution for Rest / unassigned | The 47-person region uses the 2023 WPP global single-year age and sex distribution, labelled imputed, with GeoNames listed-place population | An official dated resident age and sex table for French Southern Territories and South Georgia and the South Sandwich Islands | All canonical regions are usable, but this small region is not directly measured |
| Representative Big Five distributions | OpenPsychometrics IPIP responses provide high-uncertainty country aggregates for the ten priority countries and population-weighted regional aggregates | Representative probability samples using a named instrument, scoring method, date, and sampling frame | Current Big Five distributions are usable as imputed population inputs, not representative psychological estimates |
| Predictive MBTI evidence | MBTI is label-only and excluded from coefficients | Population-specific joint MBTI-and-outcome data with held-out validation | MBTI can filter a result but cannot drive an action |
| IPUMS International joint distributions | WDI country marginals remain inherited and joined filters use explicitly labelled independence estimates | A licensed, versioned extract with `PERWT`/`HHWT`, geography, codebook, and disclosure-safe aggregates mapped to ISCED and ISCO | No measured person-level income × education × household or other joint rates are available |
| Broader ideology coverage | WVS Wave 7 weighted items provide separate economic, state, and cultural axes for the ten priority countries; missing countries inherit population-weighted regional aggregates | Additional named WVS waves or authorized ESS/Pew extracts with questionnaires, analysis weights, dates, and separate item maps | Priority places can sample each axis, while inherited regions and uncovered countries retain higher uncertainty |
| Direct individual income distributions | WDI GNI PPP and Gini parameterize a labelled lognormal estimate for each priority country | Weighted person-level income records with unit, reference period, top-coding rules, and geography | Income shares are estimates and cannot support measured tail or joint-income claims |
| Direct MBTI population distributions | A high-uncertainty Big Five threshold proxy keeps MBTI available as label-only | A representative MBTI instrument and population-specific joint MBTI-and-outcome data with held-out validation | The proxy cannot fit a coefficient or drive agent actions |
| Individual Schwartz value distributions | Published culture-level orientation means are crosswalked to ten normalized basic-value labels; Bangladesh uses a regional estimate | Weighted individual PVQ/SVS responses with a versioned scoring map | Current distributions are imputed culture-level inputs with high uncertainty |
| WorldPop city-boundary aggregation | GeoNames populations and existing GHS urban-centre matches remain the visible fallback | A dated city-boundary source plus zonal aggregation of the official 1 km WorldPop raster | Point sampling is not presented as a city population |
| Representative conditional choice rates | One `FAKE` repost/ignore fixture and one news row kept as hint-only with a 0–1 interval | Tier 1 transaction or mobility data, Tier 2 time-use diaries, or a representative behavior survey with an exact denominator | The news hint cannot become a coefficient; the organizer lists the survey needed to close it |
| Executable shared decision programs | Launch is blocked when any selected agent lacks a confirmed decision tree backed by an explicitly promoted shared behavior receipt | Import linked trait, place, time, context, and outcome observations; validate or fit them on held-out data; promote them; then confirm the resulting tree | The installed marginal and attitude data can generate population traits, but it cannot honestly supply action probabilities by itself |
| Durable weekly leader and narration workflow | Selected-provider leader and narration endpoints return provenance, but Simulation runs do not schedule, cache, or persist those calls | A run-level leader roster, weekly aggregate-state prompts outside the numeric tick, cache keys, durable decisions, cost logs, and a results view | AI source selection governs every available call, while leader and narration calls are not yet part of the Rust run lifecycle |
| Interaction-driven routine mutation | Interaction trees apply atomic numeric state and relationship changes; a confirmed routine-add/remove effect is rejected before launch | A versioned Rust routine-state column and deterministic next-tick mutation semantics | Interaction outcomes can change health, mood, opinion, and relationships, while they cannot yet add or remove a schedule at runtime |
| Compatibility aggregate action coupling | The Simulation runner durably records Rust decision paths, routine actions, travel, interactions, and their evidence; the older aggregate compatibility runner retains a separate action graph | Fold the new Rust agent records into the older aggregate snapshot format or retire that compatibility path | The Simulation tab is auditable end to end, while the collapsed compatibility run cannot show the same per-agent causal detail |
| Full system catalog | One thin signal-spread smoke config only | Later prompts adding each system as a validated DSL config with data and backtests | Pandemic, controversy, election, brand, sports, environment, and zombie products are intentionally not built here |
| Complete real marginal coverage | Live Data organizer totals and source-specific loaders | Dated, licensed city/country imports promoted through the existing review flow | Missing, inherited, and imputed cells remain visible; no plausible defaults are inserted |
| Production authentication and uploader identity | Local user and local run scope | Authentication, authorization, retention rules, and audit identities | Current scope boundaries are functional on one trusted local server |

The ad-testing product direction remains undecided. The framework can represent it as DSL state, media, funnel transitions, and backtests after the product scope and calibration data are chosen.
